# Support, bug reports and feature requests

certoutage is maintained by one person. Every message is read.

## A feature you need is missing

The supported model is deliberately limited (see *Scope* in the README).
If your work needs something that is not implemented yet, such as another
fading model, path-loss exponent, number of elements, interference model or
output, please ask for it:

- open a **feature request** on the issue tracker:
  <https://github.com/HubHubHubHubHub/certoutage/issues/new/choose>;
- say what you need, and for which work (a paper, a thesis, a design study).
  Knowing the use helps decide what to certify first.

If it can be done in a reasonable time, it will be implemented, and you will
be told on the issue when it is released. GitHub notifies you of every reply
and of the closing of an issue you opened, so you need do nothing else.
If it cannot be done soon, you will be told why, and what is possible.

## Something is wrong

Open a **bug report** on the same tracker. A wrong certified result, an
enclosure that does not contain the true value, or a crash are the most
important reports this project can receive. Please give the version
(`certoutage.__version__`), Python version, operating system, and the
shortest code that shows the problem.

## Questions and other feedback

Open an issue with the **question** template. Comments on the documentation,
on the contract, or on how you use the package are welcome too.

## Collaborations and private messages

Collaborations are welcome. For them, or for anything you would rather not
ask in public, write to the author at the e-mail address given in his
papers on HAL, for instance the
[Letter](https://hal.science/hal-05879102); his other papers are listed
under his [HAL identifier](https://hal.science/search/index?q=authIdHal_s:victor-rabiet).
